# GFL2 Tools

> **Girls' Frontline 2를 위한 로컬 중심 편성 · 리몰딩 · 택틱 보조 도구**

GFL2 Tools는 **소녀전선 2: 망명(Girls' Frontline 2)** 플레이에 필요한 보유 데이터 관리, 제대 편성, 리몰딩 최적화, 스킬 사이클, 택틱 OCR/오버레이, 요리 계산 등을 하나의 Windows 데스크톱 프로그램에서 다루기 위한 프로젝트입니다.

메인 프로그램은 **게임 프로세스, 게임 메모리, 네트워크 패킷, 게임 설치 파일을 직접 읽거나 수정하지 않습니다.** 사용자 데이터는 수동 입력, OCR, 호환 CSV 번들 또는 GF2Tools 백업을 통해 관리하고, 인형·무기·키·이미지 등 프로그램 기본 데이터는 GF2Tools 전용 데이터 패키지에서 내려받습니다.

**현재 프로그램 버전: 1.0.3**  
**라이선스: GNU GPL v3.0 (`GPL-3.0-only`)**

## 프로그램이 하지 않는 일

GFL2 Tools 1.0.0 메인 프로그램에는 다음 기능을 포함하지 않습니다.

- 게임 네트워크 패킷 캡처
- 게임 서버와의 세션 가로채기
- 게임 프로세스 메모리 접근
- 게임 설치 폴더 자동 탐색 또는 스캔
- AssetBundle 인덱싱 또는 언팩
- 게임 파일 수정
- 사용자 보유 데이터를 외부 서버로 업로드

메인 런타임에는 `mitmproxy`, `UnityPy` 같은 패킷 캡처/게임 리소스 언팩용 핵심 의존성도 포함하지 않습니다.

프로그램이 외부 네트워크에 접근하는 경우는 크게 두 종류뿐입니다.

1. **GF2Tools 프로그램 자체의 새 Release 확인/다운로드**
2. **GF2Tools용 프로그램 기본 데이터와 이미지 다운로드**

사용자 보유 데이터, 제대, 택틱, 리몰딩 설정은 이 업데이트 경로로 전송하지 않습니다.

## 빠른 시작

### 일반 사용자 — Windows 실행형 Release

정식 Release에서는 다음 파일을 사용합니다.

```text
GF2Tools.exe
```

1. `GF2Tools-vX.Y.Z-win64.zip`을 원하는 폴더에 압축 해제합니다.
2. `GF2Tools.exe`를 실행합니다.
3. 처음 사용하는 경우 **데이터 동기화**에서 프로그램 기본 데이터를 확인합니다.
4. 사용자 데이터가 있다면 CSV 번들 또는 기존 GF2Tools 백업을 가져옵니다.
5. 별도 데이터가 없다면 **수동으로 입력** 또는 **리몰딩 OCR**을 사용합니다.
6. 중요한 설정을 마친 뒤에는 **백업 · 복원 → 모두 백업**을 한 번 만들어 두는 것을 권장합니다.

공식 Windows 실행형 패키지에는 GUI 실행에 필요한 Python/Qt 구성과 OCR용 Tesseract가 함께 포함되므로 일반 사용자는 별도의 Python 환경을 준비할 필요가 없습니다.

### 소스 Release를 사용하는 경우

소스에서 실행할 때는 **Python 3.11~3.13 64-bit**가 필요합니다. 프로젝트의 전용 런타임은 `.gfl2_runtime/`에 준비되며 사용자 데이터가 저장되는 `data/`와 분리됩니다.

## 데이터 구조

GFL2 Tools는 데이터를 **사용자 데이터**와 **프로그램 기본 데이터**로 분리합니다.

### 1. 사용자 데이터

사용자가 직접 생성하거나 가져온 데이터입니다.

- 보유 인형 및 인형 자체 레벨
- 보유 무기
- 보유 리몰딩
- 장비/키 설정
- 제대 구성
- 제대별 이미지 선택
- 인형 공통 스킬 사이클
- 제대별 스킬 사이클
- 리몰딩 계산 레벨 및 추천 설정
- 사용자 정의 카테고리
- 택틱과 오버레이 상태

주요 영속 데이터는 SQLite와 `data/` 내부 JSON 파일에 저장됩니다.

### 2. 프로그램 기본 데이터

GF2Tools가 기능을 제공하기 위해 사용하는 공용 기준 데이터입니다.

- 인형 목록과 기본 메타데이터
- 무기 목록
- 공용키 / 고유키 / 도약키
- 리몰딩 속성과 부착물 카탈로그
- 인형 초상화 / 전신 / 스킨 이미지 메타데이터
- 게임 버전 및 데이터 버전 정보
- 설명과 UI 표시용 rich-text 원본

프로그램 기본 데이터는 사용자 보유 데이터를 덮어쓰지 않습니다.

### 3. Reference override 구조

프로그램에는 실행에 필요한 최소 레퍼런스가 포함되며, 업데이트된 데이터가 설치되면 `data/reference_data/`의 갱신된 레퍼런스가 우선 사용됩니다.

설치된 프로그램 자체 파일을 수정하지 않고 `data/` 아래에 override를 두기 때문에 프로그램 업데이트와 사용자 데이터 관리가 서로 충돌하지 않습니다.

## 아키텍처

GFL2 Tools는 **PySide6 UI → Service → Repository/Storage** 구조를 중심으로 구성되어 있습니다.

```text
                         ┌────────────────────────┐
                         │      PySide6 UI        │
                         │ pages / dialogs/widgets│
                         └───────────┬────────────┘
                                     │
                   UI 요청 / ViewModel / Worker 결과
                                     │
                                     v
                         ┌────────────────────────┐
                         │    Service Layer       │
                         │                        │
                         │ dolls / formations     │
                         │ remoldings / optimizer │
                         │ OCR / tactics / backup │
                         │ updates / assets       │
                         └───────┬────────┬───────┘
                                 │        │
                     domain data │        │ reference/cache
                                 v        v
                    ┌────────────────┐  ┌──────────────────┐
                    │ Repository     │  │ JSON / File Cache│
                    │ + SQLite       │  │ + Atomic I/O     │
                    └───────┬────────┘  └────────┬─────────┘
                            │                    │
                            └─────────┬──────────┘
                                      v
                             ┌─────────────────┐
                             │     data/       │
                             │ user + cache    │
                             └─────────────────┘
```

### UI 계층

`gfl2tool.qtui`는 화면 표현과 사용자 조작을 담당합니다.

- 메인 페이지와 내비게이션
- 인형/제대/리몰딩/택틱 편집 창
- 테마와 공용 위젯
- 이미지 선택기
- 색상/오버레이 설정
- 화면 영역 선택
- rich-text 표시

UI 계층은 SQLite에 직접 SQL을 실행하지 않고 서비스/저장소 계층을 사용합니다.

### Service 계층

`gfl2tool.services`는 실제 애플리케이션 동작을 담당합니다.

주요 책임은 다음과 같습니다.

- 인형/제대/리몰딩 데이터 조작
- 리몰딩 추천과 최적화
- 스킬 사이클 저장과 조합
- 사용자 카테고리
- OCR 결과 가져오기
- 택틱 장비 및 키 처리
- 데이터 import/export
- 백업과 복원
- 프로그램 기본 데이터 업데이트
- 이미지 lazy cache
- GF2Tools 프로그램 자체 업데이트

페이지가 기능 구현을 직접 소유하지 않고 서비스에 위임하기 때문에 UI 변경과 데이터 로직 변경을 분리할 수 있습니다.

### Repository / Storage 계층

`repository.py`와 저장 관련 모듈은 SQLite와 파일 시스템 접근을 담당합니다.

- SQLite 영속 데이터
- 원자적 JSON 쓰기
- 설정 및 사용자 상태
- 데이터 백업용 일관된 DB snapshot
- 업데이트/복원 staging

가능한 경우 파일은 임시 파일 작성 후 원자적 교체를 사용해, 저장 중 프로그램이 종료되더라도 반쯤 작성된 JSON이 남는 위험을 줄입니다.

### Worker 구조

OCR, 최적화, 데이터 동기화처럼 시간이 걸리는 작업은 UI thread에서 직접 수행하지 않고 worker 경계로 넘깁니다.

따라서 긴 작업 중에도 창이 멈춘 것처럼 보이지 않도록 진행 상태를 UI에 반환합니다.

### OCR 구조

택틱과 리몰딩 OCR은 Tesseract를 사용합니다.

```text
원본 이미지
   │
   ├─ 전처리 / 영역 분석
   │
   ├─ OCR 후보 생성
   │
   ├─ 다중 패스 비교·보정
   │
   └─ 사용자 확인 / 국소 재인식
```

택틱 OCR에서는 전체 결과가 대부분 정확하고 일부만 틀린 경우를 고려해, **잘못된 후보만 선택하고 원본에서 영역을 다시 지정해 해당 후보만 재인식**할 수 있습니다.

### 네트워크 경계

네트워크 접근은 임의의 UI 코드에서 수행하지 않고 별도 서비스 경계로 제한합니다.

```text
GF2Tools program update  ──> GitHub Release
GF2Tools program data    ──> Release / static API
Missing image asset      ──> verified static asset cache
```

사용자 보유 데이터와 택틱을 업로드하는 경로는 없습니다.

## 주요 기능 상세

### 보유 현황

보유 인형, 무기, 리몰딩, 키를 사용자 데이터 기준으로 관리합니다.

- 인형 자체 레벨 표시
- 인형별 이미지/초상화 선택
- 무기 및 키 설명 표시
- 게임 데이터의 `<color>`, `<size>`, `<b>`, `<i>`, `<u>` 등 허용 마크업을 Qt rich-text로 안전하게 변환
- **리몰딩 CSV 내보내기**

임의 HTML을 그대로 실행하지 않고 허용된 표현 태그만 변환합니다.

### 제대 편성

제대마다 인형 구성과 운용 설정을 따로 유지할 수 있습니다.

- 제대 슬롯 편집
- 전역 리몰딩 계산 레벨
- 인형별 개별 계산 레벨
- 제대별 스킬 사이클 override
- 제대 슬롯별 초상화 선택
- 제대 슬롯별 전신/스킨 선택

전역 리몰딩 계산 레벨은 숫자를 바꾸는 즉시 적용되지 않습니다. **`적용` 버튼을 눌러야 실제 계산 조건이 바뀌도록 설계**해 실수로 전체 결과가 변경되는 것을 줄였습니다.

### 인형 레벨과 리몰딩 계산 레벨

두 값은 서로 다른 개념입니다.

- `dolls.csv`의 `level` → **인형 자체 레벨**
- 리몰딩 계산 레벨 → **리몰딩 목표/계산을 위한 가상 조건**

리몰딩 계산 레벨 기본값은 **Lv.60**입니다.

```text
인형별 개별 계산 레벨이 있으면
    개별 계산 레벨 사용
그렇지 않으면
    현재 화면의 전역 계산 레벨 사용
```

따라서 실제 Lv.60 인형을 데이터에서 변경하지 않고도 Lv.45 조건으로 가정해 리몰딩 결과를 시험할 수 있습니다.

### 리몰딩 최적화

리몰딩 최적화는 단일 인형 추천과 여러 인형 간 실제 보유 리몰딩 배분을 구분합니다.

주요 설정:

- 목표 스탯
- 계산 레벨
- 장착칸
- 평가 기준
- 사용자 카테고리 단위 일괄 설정
- 센티넬 / 뱅가드 / 불워크 / 서포트 역할 단위 일괄 설정

상단의 **계산 방식** 창에서 추천 점수, 옵션 등급, 가중치, 계산 레벨이 결과에 어떻게 반영되는지 확인할 수 있습니다.

### 스킬 사이클

스킬 사이클은 **돌파 수와 분리된 T1~Tn 한 세트**를 기본 모델로 사용합니다.

- `+ 다음 T 추가`로 길이 확장
- Shift/Ctrl로 여러 T 선택
- 선택한 구간을 뒤에 반복 복제
- 보유 현황의 **일반 사이클** 저장
- 제대 편성의 **제대 전용 사이클** 별도 저장
- 두 사이클은 기본적으로 독립적이며 편집창에서 필요할 때 서로 값을 복사 가능
- 택틱의 사용 인형은 사이클이 기본 빈칸이며, 인형별로 일반/제대 사이클을 명시적으로 불러오거나 택틱 전용으로 직접 편집
- 택틱 사용 인형 순서는 사이클을 조합할 때의 표시 순서로 사용
- 이미지 OCR/JSON로 들어온 기존 T1~Tn은 자동으로 바꾸지 않음
- **`내 인형 사이클로 교체…`**를 눌렀을 때만 현재 택틱 인형에 불러온 일반/제대/직접 사이클로 T1~Tn 문구를 명시적으로 대체

따라서 외부 택틱을 불러온 직후에는 원본 사이클을 그대로 검토할 수 있고, 내 인형 세팅으로 바꾸고 싶을 때만 버튼을 눌러 교체할 수 있습니다. 격자·배치·엄폐물·메모는 유지됩니다.

### 택틱

택틱은 직접 작성하거나 이미지 OCR을 이용할 수 있습니다.

OCR 결과는 다음처럼 구분해 표시합니다.

```text
제대 배치
T1
T2
T3
...
```

인식 후에는:

- 격자 요소 직접 드래그 이동
- 인형/보스/지형/화살표 위치 수정
- 특정 후보만 다시 OCR
- 원본 이미지에서 사용자가 재인식 영역 직접 지정
- 사용 인형 순서 위/아래 변경 및 저장된 제대에서 사용 인형 가져오기
- 공용키/고유키 직접 텍스트 입력
- 연결한 내 인형 사이클로 기존 OCR/불러온 T1~Tn을 수동 교체

등의 후처리가 가능합니다.

### 택틱 오버레이

오버레이는 한 번에 하나만 실행합니다.

- 실행 중에는 실행 버튼 비활성화
- 중복 오버레이가 감지되면 하나만 유지
- 닫을 때 위치/크기/투명도 저장
- 다음 실행에서 마지막 위치 복원
- 오버레이를 보면서 크기와 색상 조정

색상은 세부 요소마다 과도하게 분리하지 않고 다음 그룹으로 관리합니다.

- 격자 배경
- 글씨
- 격자 선
- 지형지물
- 기타 요소

### 요리 계산기

단일 인형뿐 아니라 여러 인형을 동시에 육성할 때 필요한 전체 수량을 계산할 수 있습니다.

- 먹일 인형 수 기본값: `1`
- 인형 수 증가 시 총 필요 재료/조리 횟수 자동 반영

## 데이터 동기화

데이터 동기화 화면은 **사용자 데이터 입력**과 **프로그램 기본 데이터 관리**를 한곳에서 처리합니다.

### 사용자 데이터 가져오기

지원 흐름:

- `gfl2-user-csv-backup` 형식의 사용자 CSV ZIP
- 기존 GF2Tools 백업 ZIP
- 수동 입력
- 리몰딩 OCR

사용자 CSV 번들은 manifest와 파일 구조를 확인한 뒤 인형/리몰딩/제대/무기/장비·키 데이터를 가져옵니다.

### 프로그램 기본 데이터

프로그램 기본 데이터 공급 우선순위는 다음과 같습니다.

```text
1. GitHub Release 완전 패키지
          │ 실패
          v
2. GitHub raw / Pages 호환 정적 API
          │ 실패
          v
3. 사용자가 준비한 오프라인 ZIP 수동 설치
```

Release와 오프라인 ZIP은 동일한 데이터 패키지 포맷을 사용하므로 결과 데이터 모델이 동일합니다.

정적 API에서는 최신 버전/manifest/core 데이터를 먼저 확인하고, 이미지가 필요한 경우에만 필요한 asset을 캐시에 내려받습니다. 다운로드된 파일은 가능한 경우 크기 및 SHA-256을 검증합니다.

현재 설치된 **게임 버전과 데이터 버전은 대시보드에서 확인**할 수 있습니다.

## 업데이트 구조

GFL2 Tools에는 서로 독립적인 두 업데이트 시스템이 있습니다.

### 1. 프로그램 자체 업데이트

GF2Tools 실행 파일과 프로그램 코드를 업데이트합니다.

```text
프로그램 시작
   │
   └─ 공식 Release 저장소에서 최신 published Release 확인
                         │
                  현재보다 새 버전?
                    │           │
                   아니오       예
                    │           │
                  종료      사용자에게 질문
                                │
                           사용자가 승인
                                │
                                v
                       Release ZIP 다운로드
                                │
                       버전 / manifest / SHA 검증
                                │
                                v
                         .gfl2_update staging
                                │
                         현재 GUI 정상 종료
                                │
                                v
                       GF2ToolsUpdater 실행
                                │
                       프로그램 파일만 교체
                                │
                      성공 ─────┴───── 실패
                       │                 │
                     재실행          rollback
                                         │
                                       재실행
```

프로그램 업데이트에서 다음 경로는 보존합니다.

- `data/`
- `.gfl2_runtime/`
- `.gfl2_update/`
- `.git/`

따라서 프로그램을 업데이트해도 사용자 DB와 설정/택틱 데이터가 프로그램 파일과 함께 덮어써지지 않습니다.

프로그램 Release 저장소 기본값은 다음 공식 저장소입니다.

`https://github.com/Kimbyeoungjang/GF2Tools/releases`

설정에서 주소를 확인하거나 변경할 수 있으며, 시작 시 자동 확인 자체는 별도 체크박스로 끌 수 있습니다.

### 2. 게임/프로그램 기본 데이터 업데이트

인형, 무기, 키, 리몰딩 기준 데이터와 이미지 등을 업데이트합니다.

이 업데이트는 GF2Tools 프로그램 버전과 별개입니다. 프로그램은 그대로 1.0.0이어도 데이터 패키지만 새 게임 버전에 맞춰 갱신할 수 있습니다.

새 데이터 버전이 확인되면 사용자에게 업데이트 여부를 묻고, Release를 우선 사용한 뒤 필요하면 정적 API로 fallback합니다.

## 백업과 복원

사용자가 실제로 구분하기 쉬운 네 종류로 나뉩니다.

| 백업 종류 | 포함 내용 |
| --- | --- |
| **모두** | 사용자 데이터 + 프로그램 기본 데이터 + 택틱 + 설정 |
| **사용자 데이터** | 보유 인형/무기/리몰딩, 제대, 계산 설정, 사이클 등 |
| **프로그램 기본 데이터** | reference, API cache, 이미지 cache 등 |
| **택틱** | 택틱 라이브러리와 오버레이 관련 상태 |

전체 백업 시 SQLite 파일을 단순 복사하지 않고 SQLite online backup API를 사용해 일관된 DB snapshot을 생성합니다.

전체 복원은 실행 중인 DB를 즉시 갈아끼우지 않고 먼저 검증/staging한 후 **다음 프로그램 시작 시 적용**합니다.

중요한 버전 업데이트나 대규모 데이터 import 전에는 **모두 백업**을 권장합니다.

## 파일과 저장 위치

실행형 Release의 기본 구조는 다음과 같습니다.

```text
GF2Tools/
├─ GF2Tools.exe
├─ GF2ToolsUpdater.exe
├─ _internal/                  # 실행 런타임
├─ ocr/                        # Tesseract + kor/eng data
├─ LICENSE
├─ THIRD_PARTY_NOTICES.md
├─ THIRD_PARTY_LICENSES/
├─ release-binary.json
└─ data/                       # 최초 실행 후 생성되는 사용자/캐시 데이터
```

`data/`의 대표적인 구조:

```text
data/
├─ gfl2.db                     # 주요 사용자 영속 데이터
├─ reference_data/             # 업데이트된 프로그램 reference override
├─ remote-api.json             # 프로그램 데이터 공급자 설정
├─ remote-api-cache/
│  └─ site/                    # 활성화된 정적 API/asset cache
├─ tactics/                    # 택틱 관련 파일
├─ portraits/                  # 사용자/캐시 이미지
└─ doll_categories.json        # 사용자 정의 인형 카테고리
```

업데이트/백업/런타임은 서로 다른 디렉터리를 사용해 책임을 분리합니다.

```text
data/            사용자 및 활성 데이터
.gfl2_runtime/   소스 실행 시 전용 런타임
.gfl2_update/    검증된 프로그램 업데이트 staging
.gfl2_build/     Release 빌드 전용 환경
release/         빌드 결과물
```

## Windows Release 빌드

정식 1.0.0부터 기본 사용자 배포물은 **소스 ZIP이 아니라 Windows EXE 패키지**입니다.

Windows에서 프로젝트 루트의 다음 파일을 실행합니다.

```text
build_release.bat
```

빌드 과정:

```text
전용 .gfl2_build 생성
        │
        v
빌드 의존성 설치
        │
        v
릴리즈 감사 + 전체 테스트
        │
        v
PyInstaller GF2Tools.exe 빌드
        │
        v
GF2ToolsUpdater.exe 빌드
        │
        v
Tesseract + kor/eng OCR 포함
        │
        v
제3자 라이선스 수집
        │
        v
release-binary.json 생성
        │
        v
Windows 배포 ZIP + SHA-256 생성
        │
        v
GPLv3 Corresponding Source ZIP 생성
```

대표 산출물:

```text
release/
├─ GF2Tools-v1.0.0-win64/
│  ├─ GF2Tools.exe
│  ├─ GF2ToolsUpdater.exe
│  ├─ _internal/
│  ├─ ocr/
│  ├─ LICENSE
│  ├─ THIRD_PARTY_NOTICES.md
│  ├─ THIRD_PARTY_LICENSES/
│  └─ release-binary.json
├─ GF2Tools-v1.0.0-win64.zip
├─ GF2Tools-v1.0.0-win64.sha256
├─ GF2Tools-v1.0.0-win64.release.json
└─ source/
   ├─ gfl2-tools-v1.0.0-source.zip
   ├─ gfl2-tools-v1.0.0-source.sha256
   └─ gfl2-tools-v1.0.0-source.release.json
```

`GF2Tools-v1.0.0-win64.zip`은 일반 사용자 배포와 프로그램 자동 업데이트용 주 자산입니다. `source/` 아래 ZIP은 GPLv3에 따른 대응 소스 배포에 사용합니다.

## 릴리즈 품질과 무결성

릴리즈 빌드는 단순히 PyInstaller를 호출하는 것으로 끝나지 않습니다.

빌드 전 감사에서 다음과 같은 항목을 검사합니다.

- 단일 프로그램 버전 소스 유지
- Python syntax / AST 오류
- 중복 메서드 및 decorator
- 미사용 import와 함수
- UI 계층의 직접 SQL 접근
- 임의 네트워크 클라이언트 추가
- 게임 프로세스/패킷/설치 파일 접근 경계 위반
- 직접 durable write
- 하드코딩된 Qt 색상
- 릴리즈 source manifest 불일치

실행형 Release에는 `release-binary.json`이 포함됩니다. 이 파일은 배포 패키지가 소유하는 파일과 각 SHA-256을 기록하며 프로그램 자동 업데이트 검증에도 사용됩니다.

소스 Release 역시 별도의 source manifest와 ZIP SHA-256을 생성합니다.

## 라이선스 및 제3자 구성요소

GFL2 Tools의 프로젝트 코드는 **GNU General Public License version 3**으로 배포됩니다.

```text
SPDX-License-Identifier: GPL-3.0-only
```

전체 라이선스 본문은 프로젝트 루트의 `LICENSE`에 포함됩니다.

### 실행형 배포의 제3자 구성요소

Windows 실행형 Release는 프로그램 실행을 위해 여러 제3자 구성요소를 함께 포함할 수 있습니다. 대표적으로:

- Qt / PySide6
- shiboken6
- Python runtime
- Pillow
- PyInstaller bootloader
- Tesseract OCR

빌드 스크립트는 가능한 라이선스/고지 파일을 `THIRD_PARTY_LICENSES/`에 모으고, 배포 관련 설명은 `THIRD_PARTY_NOTICES.md`에 기록합니다.

GPLv3 프로젝트의 실행형 배포와 함께 대응 가능한 소스 Release도 생성합니다.

### 게임 관련 권리

Girls' Frontline 2, 게임 명칭, 캐릭터, 이미지, 원본 게임 데이터 및 기타 관련 자산의 권리는 각 권리자에게 있습니다.

GFL2 Tools는 해당 게임의 공식 클라이언트가 아니며, 프로그램 코드를 GPLv3로 배포한다는 사실이 게임 원본 자산에 대한 권리를 부여하는 것은 아닙니다. 데이터 패키지에 제3자 저작물이 포함되는 경우 배포자는 해당 저작물의 이용·재배포 조건을 별도로 확인해야 합니다.

## 프로젝트 원칙

GFL2 Tools 1.0.0은 다음 원칙을 기준으로 유지됩니다.

> **게임 클라이언트에는 개입하지 않고, 사용자가 가진 데이터와 공개적으로 배포된 프로그램 기준 데이터를 로컬에서 정리·계산·시각화한다.**

- 사용자 데이터는 로컬 우선으로 관리합니다.
- 프로그램 업데이트와 게임 데이터 업데이트를 분리합니다.
- 실제 데이터와 계산용 가상 설정을 분리합니다.
